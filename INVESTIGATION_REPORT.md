# Отчёт по исследованию проблем запуска stage-env

**Дата:** 2025-10-30  
**Лог:** `stage-env_20251030_172814.log`  
**Статус:** Анализ завершён, готов к исправлению

## 🔍 Основные проблемы

### Проблема #1: Очистка данных после Phase1 snapshot
**Когда:** Строка 174 в логе: `node_data_cleaned_and_recreated nodes=8`
**Что происходит:**
- После создания phase1 snapshot вызывается `_clean_node_data()`
- Это очищает ВСЕ данные нод, включая GDB ROOT нод
- Node list который был в GDB ROOT нод ПОЛНОСТЬЮ удаляется
- MASTER ноды стартуют с пустым GDB

**Последствия:**
- MASTER ноды не могут получить node list через GDB sync (его нет в ROOT нодах)
- Все команды регистрации падают с exit_code=253
- Links не устанавливаются (для links нужен node list)

### Проблема #2: Exit code 253 при GDB sync и регистрации
**Когда:** Строки 250-252, 212-226
**Что происходит:**
- ROOT ноды (1,2,3) возвращают exit_code=253 при `net get status`
- Все попытки регистрации MASTER нод возвращают exit_code=253
- Node list команда также возвращает exit_code=253

**Вероятные причины:**
- Сеть не в правильном состоянии (возможно OFFLINE или не инициализирована)
- CLI команды не могут выполниться из-за отсутствия node list
- Может быть связано с тем что данные были очищены после snapshot

### Проблема #3: Node list не загружается на MASTER нодах
**Когда:** Строки 200-202, 290-314
**Что происходит:**
- После GDB sync node list так и не появляется на MASTER нодах
- Проверка показывает "No records" для всех 3 MASTER нод
- Через 60 секунд: 0/3 нод имеют node list

**Причина:**
- Node list был удалён из GDB ROOT нод при очистке данных после snapshot
- Нет источника для синхронизации

### Проблема #4: Links не устанавливаются
**Когда:** Строки 276-286
**Что происходит:**
- После soft_reconnect links не устанавливаются
- Timeout через 60 секунд, 0/3 нод имеют links

**Причина:**
- Для установки links нужен node list
- Node list пустой → links не могут быть установлены

## 🎯 Корневая причина

**ОШИБКА В ПОРЯДКЕ ОПЕРАЦИЙ:**

```python
# Текущий порядок (НЕПРАВИЛЬНЫЙ):
1. Pause containers
2. Clean node data  ← ❌ Это удаляет GDB данные!
3. Create snapshot
4. Unpause containers
```

**Правильный порядок должен быть:**
```python
1. Pause containers
2. Create snapshot  ← Сначала snapshot с данными
3. Clean node data   ← Потом очистка (если нужно)
4. Unpause containers
```

**ИЛИ:**

```python
# Вариант 2: Не очищать данные после phase1 snapshot
1. Pause containers
2. Create snapshot
3. Unpause containers
# НЕ очищать данные! Они нужны для MASTER нод
```

## 🔧 План исправлений (БЕЗ выполнения)

### Исправление #1: Изменить порядок операций в phase1 snapshot
**Файл:** `tests/stage-env/src/network/manager.py`  
**Строки:** ~410-412

**Текущий код:**
```python
self.compose.pause()
self._clean_node_data()  # ← УДАЛЯЕТ GDB данные!
await self.create_clean_snapshot(name=phase1_snapshot_name)
```

**Исправление:**
```python
self.compose.pause()
# НЕ очищать данные - они нужны для MASTER нод!
# Snapshot создаётся с текущими данными (включая GDB)
await self.create_clean_snapshot(name=phase1_snapshot_name)
# Данные очищаются только при восстановлении snapshot, не при создании
```

### Исправление #2: Проверить зачем нужна очистка перед snapshot
**Вопрос:** Зачем `_clean_node_data()` вызывается перед snapshot?
**Ответ:** Возможно для удаления тестовых артефактов, но это удаляет критичные GDB данные!

**Решение:** 
- Либо убрать очистку перед phase1 snapshot
- Либо очищать только тестовые данные, но не GDB
- Либо очищать только ПОСЛЕ того как snapshot создан и восстановлен

### Исправление #3: Улучшить обработку exit_code=253
**Файл:** `tests/stage-env/src/network/genesis_validator.py`  
**Строки:** ~216-229

**Текущий код:** Просто логирует warning и продолжает

**Исправление:**
- Добавить проверку состояния сети перед sync
- Если exit_code=253, попробовать привести сеть в ONLINE состояние
- Добавить retry логику с экспоненциальной задержкой

### Исправление #4: Проверить что происходит с ROOT нодами после очистки
**Проблема:** После очистки данных ROOT ноды могут быть в неправильном состоянии

**Решение:**
- После unpause проверить что ROOT ноды всё ещё ONLINE
- Проверить что node list сохранён в GDB ROOT нод
- Если нет - перезагрузить node list перед стартом MASTER нод

## 📝 Выводы

1. **Главная проблема:** Очистка данных после phase1 snapshot удаляет GDB данные ROOT нод, включая node list
2. **Exit code 253:** Следствие проблемы #1 - сеть не может работать без node list
3. **Node list не загружается:** Потому что его нет в GDB ROOT нод (был удалён)
4. **Links не устанавливаются:** Потому что нужен node list
